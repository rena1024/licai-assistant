# 账号初始化与本机恢复（A02）

本阶段提供账号服务、初始化 API 和本机恢复命令；登录/改密页面及完整会话交互在 A03 接入。
持仓等业务权限仍待 A04～A10 完成，因此 A02 完成不代表多用户版本可以投入日常使用。
用户管理页面在 A10 接入，当前没有临时开放的、接受客户端管理员 ID 的用户管理 API。

## 初始化凭据

沿用 [运行目录说明](runtime-data.md) 的 `LICAI_DATA_DIR`，启动服务与管理命令必须使用同一配置。
项目有旧库时，需要显式选定新的空目录，例如在项目根目录设置：

```bash
export LICAI_DATA_DIR="$PWD/runtime-data"
```

首次生产启动在空库生成 256 bit 随机初始化凭据，只打印文件位置，不打印凭据。
也可以只运行本机命令生成凭据，无需启动服务：

```bash
python scripts/admin_recovery.py bootstrap-token
```

凭据文件位于运行目录的 `config/bootstrap-token-<随机标识>`，新建文件在 POSIX 下权限为 `0600`。
数据库只保存 SHA-256 摘要、文件标识、创建/到期时间和消费状态，不保存凭据原文。
每代凭据使用独立文件；数据库提交前不会覆盖上一代有效文件。

- 有效期固定 24 小时；重复运行命令不会延长有效期。
- 过期或文件丢失时，在部署机器执行以下命令轮换。命令返回新的文件位置，旧凭据立即失效。
- 初始化成功后凭据被消费，文件尽力清理；即使文件删除失败，旧凭据也不能再次使用。
- 已有管理员后，即使传入 `--renew` 也不会重新生成凭据或创建第二个管理员。

```bash
python scripts/admin_recovery.py bootstrap-token --renew
```

初始化前不会恢复数据库中的旧版外部服务配置或启动个人后台任务；初始化完成后重启才进入后续启动流程。
过期或文件缺失不会由匿名网页自行生成新凭据，仍需本机命令处理。

## 初始化 API 合同

| 接口 | 输入 | 结果 |
|---|---|---|
| `GET /api/auth/bootstrap/status` | 无 | 只返回 `initialized`、`credential_available`，不返回凭据或文件路径 |
| `POST /api/auth/bootstrap` | JSON：`token`、`username`、`password` | 首次成功返回 201 与不含密码哈希的账号信息；完成后再次提交返回 409 |

初始化请求上限为 16 KiB，只接受 JSON；额外字段被拒绝。校验错误不会回显密码或凭据。
浏览器带 Origin 时必须与请求目标同源。初始化需要有效本机凭据，不提供匿名密码恢复接口。
初始化凭据消费、管理员创建和成功审计在同一个 SQLite 写事务内提交，数据库唯一索引保证最多一个管理员。

账号名为 3～64 位，以字母或数字开头，允许 Unicode 字母/数字、点、下划线、连字符；
使用 NFKC 及大小写折叠后的规范值存储，因此 `UserA` 与 `usera` 是同一个账号名。
密码为 12～128 个字符，不裁剪空格，不规定字符组合。
密码使用 [pwdlib 的推荐 Argon2 哈希](https://frankie567.github.io/pwdlib/reference/pwdlib/)，
依赖锁定为本轮验证的 `pwdlib[argon2]==0.3.1`。

发现持仓、交易、现金流、问答等无归属历史业务或实际用户配置时，拒绝初始化，不自动分配给管理员。
空库自动生成的迁移标记与原始券商模板除外；已修改的券商模板也会阻止初始化。
公开行情缓存可保留。账号结构记录 `account_schema_version=1`；不兼容版本会停止初始化/恢复。

## 本机恢复管理员密码

在部署机器、项目目录、同一虚拟环境和同一 `LICAI_DATA_DIR` 下执行：

```bash
python scripts/admin_recovery.py recover
```

命令要求交互式终端，两次隐藏输入新的临时密码；不接受密码参数、管道或重定向输入。
恢复命令只校验现有数据库版本，不重建账号、不初始化空库、不触发业务迁移。
恢复成功后：

1. 唯一管理员保持原 ID 和稳定 UUID，原密码哈希被替换。
2. `auth_version` 增加、该管理员所有旧设备会话撤销，其他用户会话不受影响。
3. 标记下次登录必须改密，记录重置时间；实际登录/提醒展示将在后续任务接入。
4. 资产、交易和历史不清空、不改写；写入一条不含密码的审计记录。

普通用户临时密码创建/重置由账号服务提供，调用时实时检查管理员身份。
服务只能创建普通用户，不提供新增管理员、角色升降或网页恢复管理员密码的接口。
普通用户重置同样撤销其所有旧会话并标记必须改密；初始化生成的管理员使用自设密码。

当前只验证了 macOS 上的恢复命令入口与隔离测试。Windows、Docker 的正式部署/恢复命令
仍待对应平台任务验证，不把这里的服务层测试当作平台实测。

## 审计与验证边界

初始化、生成/轮换凭据、创建用户、密码重置和本机恢复，从首次实现起记录结构化审计。
成功审计与账号变更同事务，审计失败则账号变更回滚；拒绝操作记录固定原因代码。
审计只接收动作、结果、内部对象 ID、原因代码和时间，不接收用户名、密码、Token、正文或异常对象。
运行日志保留、Trace 到期和审计清理策略在 D03 后续完成，本轮只完成其基础写入部分。

离线验证命令：

```bash
python -m pytest tests/test_account_bootstrap.py -q
python -m pytest -q
```

这些测试不会读取真实凭证、调用外部模型或发送通知。
