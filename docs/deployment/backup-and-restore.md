# 本机备份与受保护恢复

管理员进入设置中的「备份与运行维护」，可以创建备份、查看恢复点元信息、临时开启 Trace。普通账号不能调用这些管理接口。页面及接口均不提供恢复点内容浏览或下载。

## 备份

运行目录 `LICAI_DATA_DIR/backups` 保存完整恢复点。使用 SQLite 备份 API 创建数据库快照，按快照复制被引用的不可变媒体、必要配置及私有连接文件；清单包含格式／数据库版本和 SHA-256 摘要。运行代际、维护状态和费用隔离状态不进入恢复点，避免恢复旧库解除保护。任何必需文件缺失或复制失败都不发布半成品。

启动时错过当天备份会补一次，运行期间北京时间20点后检查，每天成功一次。自动备份保留30天，手动与保护备份各至少保留最近5份及30天；始终保留最新有效恢复点。备份失败显示在管理员运行状态并记录固定事件；消息中心通知在 C05 接入后补齐，不调用外部通知。

备份包含全部用户业务、密码散列及私有连接凭证；目录仅供本机运行账号访问，禁止放入 Git、公共网盘或静态服务目录。文件权限保护不等于加密。本机磁盘故障仍需独立的离机保护策略。

## 恢复

选择恢复点后，必须完整输入其标识，点击「确认恢复并重新登录」。这会覆盖全部用户当前数据。

服务先验证摘要、数据库完整性和兼容版本，再进入持久维护态，使旧请求和后台任务代际失效，断开 WebSocket，等待数据库连接排空；之后创建当前状态的完整保护备份。原文件全部保存后才发布恢复文件，数据库最后替换。发布失败会回滚；回滚也失败时保留维护态与恢复日志，修复存储问题后重启，服务在初始化业务前重试回滚。不要手动删除 `.restore-*` 或 `config/runtime-state.json`。

成功后撤销所有旧登录、将运行中问答置为中断、停用自动 AI，并清理进程缓存、重载数据库中的代理／TDX 配置。恢复前的仅本地偏好按稳定用户 UUID 保留更严格设置。LLM配置（当前门禁关闭）、`.env` 与进程环境配置需要重启后生效；Shell 环境仍优先于备份配置。

当前云端及尚未迁移的 AI 从服务端保持关闭，没有环境开关。费用账本核对及恢复后的待投递消息联动分别在 B02、C05～C07 完成后接入，不能把本阶段基础恢复当作这些功能已验收。

该屏障针对单进程服务；不要用多 worker 或其他进程并发修改运行目录。离线管理／诊断脚本应先停止服务，完成后再启动。不要让另一个实例共享同一数据目录。

## 健康检查与验证

匿名 `GET /api/health` 只检查本机维护状态及数据库可读性，正常200、维护／未就绪503，不调用模型、行情源或通知渠道，也不回显配置与路径。

确定性测试：`venv/bin/python -m pytest tests/test_backup_consistency.py tests/test_restore_safety.py tests/test_batch_a_gate.py tests/test_audit_privacy.py -q`。测试使用隔离临时目录和合成数据，不对当前业务执行恢复。Docker实测与未验证平台见 [Mac Docker 指南](macos-docker.md)。
