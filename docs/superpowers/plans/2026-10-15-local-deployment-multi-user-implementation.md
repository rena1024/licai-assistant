# 本机部署与多用户理财助手 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有单用户项目分批交付为可本机持久运行、用户数据隔离、支持受控多模型与独立数据检索的理财助手，并完成 macOS／Windows 约定范围验证。

**Architecture:** 延续 FastAPI、React、SQLite；单进程负责后台调度与全局本地队列，持久化任务、会话、预算预留及通知状态。先建立身份和运行数据边界，再统一 AI 出口，随后接入独立数据与搜索、通知，避免先开放功能再补权限和费用约束。

**Tech Stack:** Python 3.12（待兼容性实测锁定补丁版）、现有 FastAPI/aiosqlite、React 19/Vite 8/Vitest、pytest、Docker Compose、Mac 原生 Ollama；不新增数据库、Redis、Celery 或 Kubernetes。

**Spec:** [需求 v0.40](../specs/2026-10-14-local-deployment-multi-user-requirements.md)。编制日期 2026-10-15。

执行状态以 `tasks/todo.md` 及 [2026-11-19 对齐记录](../../../tasks/evidence/2026-11-19-alignment.md) 为准；后者登记基线之后的需求增补、冲突及提交证据。以下 2026-10-19 状态为历史记录。

## 1. 建议顺序与优先级

**必须先完成：运行数据边界、认证和完整数据隔离、基础备份恢复；开放云端 AI 之前必须完成统一调用出口与预算账本。** 这两组是强依赖。行情可靠性、用户模型选择和本人用量属于高优先级；完整诊断界面、邮件渠道和管理界面细节可后做。

| 级别 | 内容 | 原因／开放约束 |
|---|---|---|
| P0：基础与保护 | 持久目录、测试隔离、账号权限、全部私有资源隔离、基本审计、备份恢复、最小健康检查 | 后续所有功能依赖；不能只隔离登录页和持仓表 |
| P0：AI 开放门槛 | 统一物理请求入口、预算预留与用量、仅本地控制、取消和任务身份 | 未通过时云端 AI 保持关闭；不先开放再补计费 |
| P1：核心能力 | 按场景选模型及备用、全部约定厂商、本地公平队列、用量提醒、行情独立备用和时效、数据中心 | 决定 AI 可用性与分析可信度；先 Ollama+现有 Anthropic 验证架构，再补齐厂商 |
| P1：信息闭环 | 应用内消息、PushPlus、独立免费搜索、私人连接配置 | 用户能看到分析依据与异常；免费额度独立于模型预算 |
| P2：后段完善 | 邮件／飞书完整投递状态机、工程诊断页面、管理展示细节、交付材料完善 | 不影响前面安全闭环；首版完成前仍必须交付 |
| 贯穿全部阶段 | 自动化测试、Windows 兼容检查、平台指南草稿、基础审计和运行可观测性 | 不应等最后才发现整个平台不能运行或审计缺失 |

不增加专门测试人员角色、不增加自行注册、不引入云服务器、不把 Ollama 强迁 Docker、不做新搜索门户。历史功能不扩展为新业务需求。

| 现有位置 | 观察 | 实施落点 |
|---|---|---|
| `database.py`、各 `api/*_routes.py` | 大量私有表/查询目前无用户边界，存在全表导出/导入 | 显式user_id、联合唯一键、资源归属检查；公共缓存保留共享 |
| `run.py`、`api/ws.py` | 启动时建后台任务，全局连接集合和调度标记 | 身份化调度、用户订阅推送、测试模式禁止启动生产作业 |
| `services/ask_runs.py`、`stock_agent.py`、媒体目录 | 问答和工具链任务需同一身份，存在运行态缓存 | 持久owner、受保护媒体、取消及迟到写入屏障 |
| `llm_client.py`及分散调用点 | Claude协议/工具绑定、隐藏重试；存在Mac专用认证路径 | 统一运行时，每个HTTP尝试独立计量；厂商适配器不擅自重试 |
| `okx_client.py`、`zsxq_client.py`、`providers/registry.py` | 私人凭证/客户端可能全局复用 | 按用户客户端与缓存，插件代码仍宿主管理 |

| `frontend/src/App.jsx`、`hooks/` | 页面状态与WebSocket生命周期需随账号清空 | 登录门禁、统一鉴权错误、关闭旧连接及重连计时器 |
| 部署与测试 | 已有pytest/Vitest；未有本轮Docker交付结构 | 延续测试；新增可复现打包与隔离测试环境，不更换工具链 |

### 接口约定

以下为**拟新增／调整合同**，不是宣称当前已有API。实现前创建类型定义与测试固定合同，再迁移调用点。

| 合同 | 约定 |
|---|---|
| `UserContext(user_id:int, session_id:str, auth_version:int)` | 仅认证依赖创建，路由不可接受客户端传入身份；私有DB接口如 `get_all_holdings(*, user_id:int)` 无默认身份 |
| `CallContext(owner_id:int\|None, scene:str, task_id:str, purpose:Literal['user','diagnostic'])` | user必须有owner；diagnostic仅管理员受控入口创建、只占全局费用，不携带用户业务正文 |
| `ModelRequest(messages, tools, response_schema, output_limit, capability)` / `ModelResult(content, tool_calls, usage, finish_reason)` | 厂商协议留在adapter；中间层保留必要工具签名，不交给前端泄露；unsupported显式报错 |
| `LLMRuntime.generate(context, request, candidate_ids)` | 只接受用户有序候选；调用前检查身份/模式/能力/取消/预算；每次物理HTTP发送均创建attempt，adapter不隐式重试 |
| `reserve_attempt(context, model_id, price_snapshot, max_cost, idempotency_key)` → `reservation_id` | SQLite `BEGIN IMMEDIATE` 内检查/预留，数据库唯一键防重复；所有4项费用容量一起成功或失败 |
| `settle_attempt(reservation_id, usage_or_unknown, provider_request_id)` | 原发起周期恰好一次结算；未知不记0、不释放，保留待核对；超预留实际费用照实记账并停止新调用 |
| `TaskContext(owner_id, task_id, cancellation_version, runtime_generation)` | 每次工具/模型步骤重查；取消或恢复后旧代际不能发布结果，计量仍结算；失败任务不自动重跑 |
| `Quote(value\|None, currency, unit, source_id, source_at, fetched_at, market_state, quality)` | 区分原始数据时间和抓取时间；缓存、休市、缺失、延迟单独表达，不凭fetch时间称最新 |
| `SearchService.search(context, query, max_results)` | 与模型服务无关；用户可禁用；credits与模型tokens分账，实际账户免费证明缺失或额度不足即暂停 |
| `NotificationService.publish(recipient_id, event_type, dedupe_key, summary)` | 先应用内，再单一活动外部渠道；外发冻结目标版本；不把已送达等同已读 |

用户另存不可复用的稳定UUID，恢复前后的安全偏好按UUID匹配，不能只按可能复用的整数ID匹配。会话凭据只在客户端保存原值，数据库保存哈希；重置通过auth_version与会话撤销共同生效。

配置采用版本号快照，保存先校验再事务替换。已发请求使用原计价快照，后续步骤读取最新权限／模式／配置。密钥不返回明文，不要求新增复杂密钥管理服务；本机文件与备份限制读取权限并明确含敏感信息。

### 技术选择与必要依赖

- 认证采用**服务端可撤销会话Cookie**，不使用难以即时撤销的纯无状态长效JWT。Cookie HttpOnly、SameSite=Lax，状态修改CSRF校验，WebSocket检查Origin；HTTPS下Secure。局域网HTTP仍有明文传输边界，不把该方案当公网发布配置。
- 密码计划新增轻量 `pwdlib[argon2]`，用于成熟密码哈希，避免自行实现密码学；现有依赖没有等价用途。测试如使用FastAPI TestClient则在测试依赖加入`httpx`，不为此引入运行时全套SDK。
- 模型优先沿用现有HTTP实现的能力，必要时以现有HTTP库适配；不同时强引全部厂商SDK。模型能力、缓存/推理token计价按真实协议fixture验证。
- SQLite单进程是本版明确运行约束，容器只开1个应用worker；并发预留仍用DB事务。扩多worker/多机需另设计队列租约与调度领导者，不在本版伪装支持。
- 运行持久目录以`LICAI_DATA_DIR`配置；数据库、用户媒体、必要配置与备份均在受控目录。测试profile拒绝加载真实.env、Keychain和生产挂载，默认出网拒绝。

模型协议实施时再次核对：[OpenAI工具调用](https://developers.openai.com/api/docs/guides/function-calling)、[Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create)、[Gemini工具调用](https://ai.google.dev/gemini-api/docs/function-calling)、[DeepSeek工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、[通义千问工具调用](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/qwen-function-calling)、[Ollama Chat](https://docs.ollama.com/api/chat)。协议文档不代表某个具体模型已通过兼容验证。

## 6. 建议运行参数

以下为实施默认值，实施验证可在不改变已确认边界的前提下调整并留记录，无需逐条再询问。金额预算与供应商价格不能凭空设定：初始均未配置，因此云端关闭，由管理员/用户填有效值。

| 参数 | 首版默认及理由 |
|---|---|
| 登录／初始化 | 会话固定30天、不滑动；初始化凭据随机256bit，本地生成后24h有效，消费一次，过期可本机重新生成；登录失败按账号+来源5次/15min限速，避免永久锁死 |
| 模型尝试 | 每个候选最多2个物理attempt（首发+1次，仅确认未消费或供应商支持幂等的可重试失败）；每个逻辑生成最多3个候选、6次物理attempt；退避1s加抖动并尊重Retry-After；超时未知是否消费不盲目同请求重发；已开始输出不透明续接，备用另开版本且独立预留 |
| 模型超时／工具 | 云端连接10s、无进展120s、单次总300s；本地无进展180s、单次总600s；单任务最多8轮工具、总15min。超时仅终止本地等待不承诺厂商不收费，按未知用量处理 |
| 本地排队 | 全局并发1；每用户最多2个等待，总20个，等待上限5min；每连续5个交互任务让出一次给已等待>=2min的后台，用户间轮转，不抢占在途 |
| 后台日程 | 上海时区；早盘09:00，允许09:00～09:15窗口，之后不补；收盘数据作业15:10按交易日历；自动AI初始关闭，启用时展示频率/成本；同用户/场景/周期活动任务去重 |
| 费用预留 | 按协议已验证tokenizer计输入上界，含工具schema/上下文/图像；无可靠估算器或单价则禁用云端。首次输出上限2048tokens、交互配置上限8192。用价格及FX快照计算最大价（未证明折扣则按未缓存价），再留10%安全量，超限先拒绝。无厂商输出上限硬约束的模型不得启用 |
| 计量异常 | 不能把超时/空usage记0；未知保留预留不随周期过期释放，并暂停该服务新云端attempt，管理员核对；实际超预留照实入账、停止新调用并告警，不截断账单掩盖超额 |
| 预算提醒／清理 | 默认80%预警、100%停止，日/月各去重；调用明细7天，未结算必要财务元数据保留至核对；日/月汇总长期保留，无提示词正文 |
| 行情刷新／时效 | 沿用现有报价缓存5s、活跃5s/空闲60s轮询；交易中来源时间落后120s标延迟、5min标旧值，按市场覆盖可调；休市用最近交易收盘/已知延迟口径，不能仅按墙钟过期；无source_at标未知时效 |
| 搜索 | 每用户10次/min、100次/day；单次最多5结果；Tavily basic/Exa经核验的有界低成本模式，禁用额外付费增强。预留实际档位credits；仅明确未消费失败重试1次、备用最多1个；未知是否消费保持预留，未知剩余额度暂停。账户可用免费额度/周期由凭证核验证据填写，不编造数值；专用key仍需核对账户是否被其他应用共享使用，不能确认剩余额度时暂停 |
| 通知 | 应用内90天；同渠道明确失败最多2次重试（1min/5min），超时未知不自动重发；同故障恢复事件各1次，同一未恢复故障最多1条/30min；业务状态与投递状态分离 |
| 备份 | 每日20:00，错过启动补1次；自动30天，手动/恢复前保护备份默认各保留最近5份且至少30天，不删唯一有效点；管理员显式清理前校验可恢复点，磁盘不足告警而非删光 |
| 审计／日志 | 审计180天，运行日志7天，Trace30min到期；配置独立；禁止正文和凭证明文。通知清理不能删除预算去重/财务依据 |
| 回归作业 | 同时1个，重复请求返回活动ID，总超时15min；隔离worker不具生产挂载/凭证，默认网络禁用，无资源则拒绝；真实连接测试不混入回归；作业协议仅含白名单用例ID，不接受命令、任意路径或脚本 |
| 性能验证目标 | 同机5个登录用户、1个本地推理运行、1000条持仓/1万交易的合成数据，非推理登录/列表API P95<1s、取消后1s内状态可见；真实AI时长只记录不统一保证。记录CPU/内存/样本和冷/热状态，供应商网络延迟单列 |

预算是本应用的调用保护，不等同供应商账单强封顶：每次预留须保守且可核验，未知usage与在途请求仍可能收费。不可通过后台重试或厂商不支持的输出限制声称绝对不会超额。
