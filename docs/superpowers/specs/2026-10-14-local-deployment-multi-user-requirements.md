## 1. 文档规则与产品目标

### 1.1 需求状态

- **已确认**：用户在此前讨论中明确接受的产品决策，后续方案不得擅自改变。
- **规则展开**：将已确认决策写成可验证的流程、数据边界或验收要求，不增加新的产品选项。
- **统一采纳（Q06-b～Q14）**：用户明确授权直接采用专业建议，不再逐条询问。已将建议及必要的保守默认规则纳入正文；Q 编号保留为决策追踪，不再表示产品审批未完成。
- **技术待设计（T 编号）**：实现机制、依赖版本、接口参数、供应商和验证环境留到实施计划核实，不属于未获同意的产品需求；只有改变已确认的功能范围、费用或权限边界时才需重新讨论。

流程：需求讨论与文档评审 → 确认产品基线 → 编写实施计划 → 审阅计划 → 用户决定是否执行。本文仅完成需求阶段的细化，不提前锁定数据库结构、API 路由或第三方依赖。

### 1.2 产品目标

将现有单用户本地理财看板扩展为可在局域网供多个用户独立使用的理财助手：

1. 本机可重复部署，登录 Mac 后自动运行，更新容器不丢数据。
2. 每人拥有独立的资产、交易、问答、通知及模型偏好。
3. 云端与本地模型按场景自由选择，失败切换受用户意愿和预算约束。
4. 行情、资讯和搜索独立于模型，来源与时效可见。
5. 管理员管理公共基础配置、费用与运行状态，不通过应用浏览他人私有业务正文。
6. 能解释“为什么不可用、为什么使用这个来源／模型、为什么产生这笔估算费用”。

### 1.3 产品定位与边界

- 保留现有资产记录、行情展示、资讯整理、风险提示和复盘功能，不增加交易执行、撮合、兑换或代客理财。
- 本机部署不保证关机、休眠、断电或断网期间仍可访问，不承诺 24×7 可用性。
- 本机部署不等于完全离线：云端模型、公开行情、资讯、在线搜索及外部通知仍需联网。
- “仅本地模型”只限制推理服务，不自动关闭独立搜索或行情、资讯抓取。
- 多用户首版面向本机和局域网使用，不按公网开放注册或商业多租户平台设计。

## 2. 范围与已有决策

### 2.1 首版确定范围

| 领域 | 已确认要求 |
|---|---|
| 部署 | 优先 Mac Docker；登录 Mac 后自动启动；数据库从空开始，不迁移现有数据 |
| 手动部署 | 至少提供 macOS、Windows 原生手动部署流程，命令按终端分别编写并验证 |
| Ollama | 保留 Mac 原生部署，与 Docker 中的理财助手分别登录自启动 |
| 账号 | 管理员、普通用户两类角色；首版管理员创建账号，未来可扩展自行注册 |
| 管理员数量（Q02-d） | 首版仅一个管理员，由首次初始化创建；只能创建普通用户，不提供新增管理员或角色升降，不允许停用唯一管理员 |
| 登录会话（Q02-e） | 默认固定有效期 30 天，后台刷新不续期；多设备共存，退出只撤当前会话，改密／重置／停用撤销所有旧会话，切换账号清除私有状态 |
| 密码重置（Q02-a） | 管理员可信，可重置临时密码但不可查询原密码；旧会话失效，登录后改密，记录操作并应用内提醒本人 |
| 管理员恢复（Q02-b） | 通过部署机器上的命令行恢复密码，Docker／原生分别提供说明；不清空业务数据，旧会话失效，重新登录并改密，无匿名网页重置入口 |
| 用户停用（Q02-c） | 支持停用与重新启用，首版不永久删除；停用撤销会话和排队任务，停止新调用与外部通知，保留数据，启用不自动补跑 |
| 首次使用（Q01） | 首个管理员凭本机生成的一次性初始化凭据创建；业务需登录；管理员清单引导，普通用户临时密码首次改密；缺 AI 配置不阻断理财 |
| 数据 | 用户持仓、交易、问答历史和通知配置独立隔离，派生数据继承用户归属 |
| 来源归属（Q03） | 公共来源由管理员管理；交易所、知识星球及个人订阅凭证由用户各自配置，私有内容、缓存及派生结果按用户隔离 |
| 模型来源 | OpenAI、Anthropic、Gemini、DeepSeek、通义千问、本地 Ollama及自定义兼容服务 |
| 模型选择 | 管理员管理接入、定价和开放范围；实际场景主模型、备用模型及顺序由用户选择 |
| 模式 | 默认云端；用户可选择仅本地，选择后不得自动转云端 |
| 模式生效（Q05-a） | 切仅本地后旧任务也不新增云端调用；在途请求尽力取消但可能计费；恢复云端仅影响后续新请求，不迁移正在本地生成的回答；每步重查权限与预算 |
| 部分回答（Q05-b） | 失败部分保留并标未完成，用户备用模型生成独立完整回答；显示切换原因与模型，各次尝试分别计量，无备用时等用户决定是否重试 |
| 取消与恢复（Q05-c） | 取消后退出排队、不新增模型／工具调用或尝试备用，保留部分内容标已取消；在途尽力取消且可能计费，迟到结果不正常发布；终态不自动重跑 |
| 无本地候选（Q04） | 允许保存仅本地模式并标记相关 AI 暂不可用；只尝试用户已配本地候选，不指定替代模型、不转云端，其他业务正常 |
| 失败处理 | 合格备用按用户顺序自动切换，可不配置备用；无备用时提示失败 |
| 本地并发 | 项目发往 Ollama 的推理默认所有用户共享并发 1；排队可取消，超时不擅自转云端 |
| 预算 | 全局与用户各有日、月预算，任一适用上限达到后停止新云端调用，尝试用户配置的本地模型 |
| 预算配置（Q06-a） | 未填不开放云端，0 表示无额度；全局及用户日月预算均为有效正数且有余额才允许云端，首版无无限预算；本地、免费搜索与理财功能照常 |
| 计价 | 人民币预算，保留原币费用；管理员手动配置单价与汇率，未定价云端模型默认不启用 |
| 周期 | Asia/Shanghai 自然日／自然月；默认 80% 预警、100% 停止；同周期同阈值去重 |
| 用量 | 本人可看自身用量与预算；管理员看全局元数据；调用明细默认 7 天，月汇总长期保留 |
| 数据管理 | 独立数据源管理页；按数据类型配置主备；股票实时价格增加独立备用来源 |
| 搜索 | 与模型完全独立；首版少量免费额度通道，耗尽后尝试其他已配置免费通道，不自动付费 |
| 通知 | 应用内默认；推荐 PushPlus，可选邮件或飞书；可存多配置，同一用户同时只启用一个外部渠道 |
| 通知引导 | 首次登录引导至少配置一个外部渠道，可稍后完成，不阻断理财或 AI 功能 |
| 告警 | 系统告警给管理员；个人提醒给本人；失败不自动换渠道 |
| 日志 | 运行日志默认 7 天；Trace 默认关闭，临时开启默认 30 分钟后关闭，始终脱敏 |
| 备份 | 每日一次，默认保留 30 天，可手动备份；本机持久存储，恢复前保护当前状态 |
| 诊断 | 管理员基础冒烟、外部连接测试、隔离回归及 Trace 入口，不设置测试人员专属角色 |

### 2.2 首版不包含

云服务和公网部署、未登录 Mac 自启动、公开注册及邮箱验证、独立测试人员角色、交易执行、通用厂商余额查询、大量搜索通道的全量接入、保证账单严格不超预算、独立的每日全市场 AI 大盘报告。

## 3. 用户角色、权限与数据归属

### 3.1 角色权限矩阵

| 功能 | 未登录 | 普通用户 | 管理员 |
|---|---|---|---|
| 首次初始化 | 仅未初始化且持有本机生成的一次性初始化凭据时 | 不适用 | 完成后凭据及入口失效，不能重复初始化 |
| 登录 | 可以 | 可以退出／切换账号 | 同普通用户 |
| 私有资产、流水、问答、复盘 | 不可访问 | 仅本人 | 仅本人，无他人浏览入口 |
| 市场行情与公开资讯页面 | 不可访问，业务页面和数据均需登录 | 可访问 | 可访问 |
| 场景模型、备用顺序、仅本地开关 | 不可访问 | 自行配置本人偏好 | 配置本人偏好，不覆盖他人选择 |
| 本人用量与预算 | 不可访问 | 只读本人，不能改额度 | 本人查看，另有管理入口 |
| 公共数据源、搜索通道、模型凭证与单价 | 不可访问 | 不可配置 | 配置、启停、测试 |
| 用户账号及预算上限 | 不可访问 | 不可管理 | 创建、停用、重置密码和配置额度 |
| 全局用量 | 不可访问 | 不可查看其他用户或全局明细 | 仅调用元数据，不含提示词和回答 |
| 备份恢复、工程测试、Trace | 不可访问 | 不可操作 | 受控执行，不扩大业务数据权限 |
| 个人外部接入凭证 | 不可访问 | 配置和使用本人接入，凭证脱敏 | 仅配置本人接入，无他人凭证或私有内容浏览入口 |

管理员最高权限是系统管理权限，不提供“以用户身份登录”或查看他人持仓、流水、问答的入口。数据库文件及整机控制权不在应用内隔离的保证范围内。Q02-a 已确认采用可信管理员前提：允许管理员重置临时密码，不承诺从技术上阻止知晓临时密码的管理员在用户改密前登录；应用仍不得提供直接浏览他人数据或代登录入口。

### 3.3 隔离生效范围

- Q03 已确认：公共行情、公共资讯与公共搜索服务由管理员管理；用户在个人接入页面维护自己的交易所、知识星球及个人订阅，不将这类凭证加入共享来源池。
- 私有接入的工具调用、授权范围、连接状态、缓存、摘要与错误信息均继承用户归属；不得通过共享同一服务端客户端、后台任务或结果缓存泄露给其他用户。
- 后端根据已认证用户确定归属，不信任客户端自报用户标识。
- 页面、API、导出、图片附件、历史、缓存、WebSocket、后台任务、通知和错误信息均受同一边界约束。
- 切换账号须关闭前一身份连接并清除私有界面缓存，不能先显示上一用户数据再刷新。
- 公共资讯原文可共享；“与我的持仓关联”、AI 摘要和个人事件日历必须按用户计算。
- 服务重启后的任务恢复也必须保留用户归属，不把无上下文的任务归给管理员。
- 用户停用、密码重置和恢复备份后的会话与任务处理见 Q02、Q09、Q12。

### 4.2 首次使用流程

**管理员流程（Q01 已确认）**：启动空实例 → 使用本机生成的一次性初始化凭据创建管理员 → 登录 → 查看配置清单 → 配置模型服务／价格并开放 → 设置全局及用户预算 → 创建用户 → 可选配置数据来源与通知 → 验证可用。清单明确每项是否完成，预算未配置按 Q06-a 不开放云端调用。

**普通用户流程（Q01 已确认）**：获得账号及临时密码 → 登录并修改临时密码 → 看见空资产与录入入口 → 按场景选择模型或仅本地 → 引导配置通知（可稍后） → 使用业务功能。后续密码重置与账号恢复遵守已确认 Q02。

除初始化、登录及必要状态检查外，业务页面和数据均需登录。必要状态检查只能暴露服务是否可用，不作为读取私有数据或配置的匿名入口。

缺少 AI 配置不能阻止手动录入资产、查看已有记录和可用行情。空数据库显示“尚未录入”，不能伪装成演示数据。预算未配置、没有模型可用等条件分别展示原因，不统一显示“系统错误”。

### 4.3 统一状态表达

| 状态 | 用户应看到的内容 |
|---|---|
| 尚未配置 | 缺少的项目、谁能完成、可继续使用什么 |
| 无数据 | 尚未录入、来源无结果或权限范围无结果，区分原因 |
| 加载／排队 | 当前阶段、可否取消，不伪造倒计时 |
| 降级 | 原因、当前实际来源／模型，以及影响 |
| 过期／不完整 | 所属时间、缺失部分、哪些统计不可靠 |
| 受限 | 个人预算、全局预算、仅本地或未开放，不暴露他人信息 |
| 失败 | 可理解原因、重试或配置入口，不回传凭证和内部堆栈 |

## 6. 模型服务与用户选择

### 6.1 服务管理

管理员可以新增、编辑、测试、启停模型服务；字段至少包括显示名称、服务／协议类型、基础地址、凭证、代理选项、可用模型标识、运行位置（云端／真正本地）、价格币种和单位、能力及最近验证状态。

- 服务接入不等于模型已开放，未定价云端模型默认不启用。
- 凭证只脱敏展示，不提供查询原值的接口。
- 模型名可手动填写；自动枚举是否提供属于体验细节，不把服务返回列表当作能力验证通过。
- 支持多个模型服务配置及自定义兼容端点，不宣称任意兼容接口支持所有高级能力。
- 模型开放范围是否区分用户／用户组未在首版确认；不得自行增加复杂授权分组。
- 更换协议、地址或模型后，应重新检查受影响能力，不能沿用旧测试结果冒充新模型验证通过。

### 6.2 场景目录

| 场景 | 输入与预期输出 | 最低能力要求 |
|---|---|---|
| 市场问答／个股问答 | 用户问题、本人上下文与工具结果 → 可追溯回答 | 文本、工具调用、适应场景上下文 |
| 资讯摘要 | 近期资讯与关联 → 结构化重点 | 文本与结构化输出 |
| 单条资讯解读 | 标题／正文／用户相关性 → 讲了什么、重要性、关联 | 文本与结构化输出 |
| 持仓早盘简报 | 个股／ETF 资讯、公告及相关数据 → 摘要与风险 | 文本与结构化输出 |
| 组合／交易复盘 | 本人交易、表现及资讯 → 客观归因／纪律回顾 | 文本与结构化输出 |
| 基本面辅助分析 | 指定事实与资料 → 结构化解读 | 文本与结构化输出 |
| 图像辅助分析 | K 线或图像与数据 → 分析结果 | 图像输入及该场景其他必要能力 |

表内涵盖现有用途，不新增交易建议。实施前盘点所有 AI 调用映射到场景，不能遗漏后台调用而继续使用写死模型。结构化输出指结果满足应用约定，不强制要求所有厂商使用同一种专有接口。

### 6.3 用户设置

- 用户在已开放的模型中选择每个场景的主模型和有序备用列表，列表可为空，设置归本人。
- 默认云端不等于管理员替用户做最终选择；推荐值不能覆盖已保存的用户配置。
- 用户可选择仅本地，作用于本人所有场景及后台任务，刷新、重启、切页后保持。
- 仅本地模式只允许真正本地模型；Ollama 端点提供的云端模型不能归为本地备用。
- 管理员关闭模型时保留用户配置并标记停用，执行跳过，尝试用户剩余合格备用；否则提示重新选择。
- 无匹配能力时显示原因，不能用简单连通测试代替工具、图像或结构化能力验证。

### 6.4 执行决策表

| 条件 | 行为 |
|---|---|
| 用户已选择仅本地 | 仅在其已选择的合格本地模型中执行，不自动转云端 |
| 云端模式、预算及模型均可用 | 从用户主模型开始，失败时有限重试／按备用顺序选择 |
| 主模型已停用或能力不足 | 跳过并记录原因，只尝试用户已配置的合格备用 |
| 用户预算或全局预算达到上限 | 跳过全部云端候选，只尝试用户配置的合格本地候选 |
| 无本地候选 | 提示“缺少可用的本地备用”，不随意选择其他模型 |
| Ollama 排队超时 | 结束等待并提示，不擅自转云端 |
| 所有候选失败 | 标记任务失败，保留可查原因和计量元数据，不无限循环 |

**Q04 已确认**：预算耗尽后只尝试用户主／备用列表中已配置的合格本地候选；没有则提示配置不足。允许用户在没有合格本地模型时保存仅本地模式，相关 AI 场景显示暂不可用并引导配置，其他业务正常。不另设管理员指定的强制替代模型，也不自动转云端。

**Q05-a 已确认**：用户模式变更优先于旧任务快照，切到仅本地后，已有任务也不得发起新的云端调用；已发出的云端请求尽力取消，但不能保证撤回，仍可能计费。预算恢复或用户重新启用云端只影响后续新请求，不把正在本地生成的回答中途迁回云端。每次重试、备用切换及下一轮工具调用前，重新检查当前权限和预算。独立搜索等工具继续遵守各自已确认的独立额度和访问规则，不能误把禁止云端模型调用解释为禁止所有联网取数。

### 6.5 失败、取消与部分结果

已确认：失败后有限重试并按用户备用顺序切换，记录原因和实际模型，服从仅本地与预算；无备用明确失败。

Q05-b 已确认的部分回答处理：

- 未产生回答时可按既定规则尝试备用；已有部分内容则保留并明确标记“未完成”。
- 仅按用户已配置的备用顺序，生成一份独立完整的新回答，不直接续接前一模型文字，不把不同模型片段混接成一个完成版本。
- 展示切换原因和各版本实际模型，失败尝试与备用调用分别计入用量；无法取得用量仍按未知规则标记，不因任务最终成功而抹掉前次尝试。
- 无可用备用时保留失败状态及已有内容，由用户决定是否重试，不自行选用其他模型或无限重试。

Q05-c 已确认的取消与恢复规则：

- 用户取消后立即退出排队，不再发起新的模型或工具调用，不再尝试备用；保留已有部分内容并标记“已取消”。
- 已发出的请求尽力取消，但可能仍计费；迟到结果不得将取消状态改为正常成功或作为正常完成结果发布，能够获取的用量仍需记录。
- 最终失败、等待超时或取消后，不因页面刷新或服务恢复而自动重跑；用户可手动重试，重试前重新检查当前模式、模型可用性与预算。

未知用量按已采纳 Q07 保留费用占用并待核实；工具结果复用等机制在技术计划中设计：

- 费用和数据工具结果复用应有记录，重试不能让用户误认为只发生一次调用。
- 对网络读超时不能假设上游没有执行，先按未知用量与费用处理，再按有限策略决定是否重试。
- 取消和终态恢复均服从上述 Q05-c 规则，不把自动恢复连接等同于重新提交业务任务。

## 7. 任务、定时执行与资源

### 7.1 任务状态

AI 任务至少区分：待检查、排队、取数／搜索、模型执行、尝试备用、成功、失败、取消、等待超时、服务重启中断。每个任务记录所属用户、场景、可见状态、实际尝试和结果；内部请求可多次，但不能把它们展示成多条重复用户问答。

已有问答的切页／刷新后查看进度能力保留；关闭浏览器或正常退出不取消已提交任务，继续按所属用户身份、当前模式、开放模型与预算执行。停用账号及主动取消按既定规则阻止后续步骤。刷新页面不能自动重新提交计费任务。

### 7.2 本地并发

- 项目发往 Ollama 的推理默认全局并发 1，所有用户、后台任务、重试和备用共用；管理员可调整。
- 排队展示状态，用户可取消本人等待请求，取消后不能继续执行。
- 超时不擅自转云端；取消等待后不能因队列恢复又执行。
- 不承诺限制其他应用直接访问同一 Ollama 的负载。
- 队列采用交互请求优先、用户间公平、后台任务防饥饿的策略；优先级只影响尚未执行请求，不中断已开始的本地推理。等待时限、最大长度和云端并发在 T03 中给出参数并验证。

### 7.3 自动任务与生命周期（Q09 已统一采纳）

| 事项 | 产品规则 |
|---|---|
| 自动简报与复盘 | 沿用已有自动能力范围，不把手动复盘等悄悄改为自动计费；按所属用户偏好和预算执行 |
| 首次启用 | 会产生模型调用的自动任务首次默认关闭，由用户看到频率和费用提示后启用；不影响已有纯数据公共任务正常运行 |
| 错过执行窗口 | 不补发已失去时效的早盘报告；保留手动生成当前摘要入口并使用真实生成时间，不伪装当时信息 |
| 任务时间 | 早盘仍围绕现有约 9:00 时段，收盘小结仍围绕交易日 15:10；具体窗口和交易日判断写入实施计划，不把手动 AI 复盘自动化 |
| 手动与后台竞争 | 未开始的交互请求优先，用户间公平调度，后台有防饥饿机制；不能让批量简报长期独占本地推理 |

运行参数在实施计划统一列出，不再将每个超时数值作为产品待确认项。

## 8. Token 用量、费用与预算

### 8.1 可见范围与记录

用户查看本人调用、Token、估算费用和日月剩余额度；管理员查看全局元数据，可按用户、场景、服务、模型、时间和状态筛选，不查看私有提示词、回答或工具正文。

每次尝试记录：任务与尝试关联、所属用户或系统归属、时间、模型、状态、耗时、输入／输出及服务提供的缓存／推理用量、价格快照、币种、汇率、费用、估算／未知标记和切换原因。

调用明细默认保留 7 天；按月汇总 Token 和费用长期保留。管理员可调整明细保留期。清理不能改变当前预算累计、历史汇总或已触发提醒。调用正文不因用量监测而复制保存。

### 8.2 费用口径

- 全局和用户预算统一人民币；保留原币费用、币种、计价单位、单价和当次汇率。
- 管理员手动维护输入、输出、缓存等适用单价与汇率；价格修改只影响后续计价，不回算历史。
- 不同服务字段不能无条件相加；例如已计入输出 Token 的推理 Token 不能再次重复收费。具体计价项映射在 T02 核实。
- 未定价云端模型标记费用未知，默认不启用，不能进入自动主备调用。
- 本地模型保留用量与耗时，云端 API 费用记零，不代表没有电力和硬件成本。
- 厂商未返回用量时明确未知，不记零；本地估算不等于厂商账单、充值余额或最终费用。

### 8.3 双层额度

| 层级 | 日额度 | 月额度 | 达上限影响 |
|---|---|---|---|
| 用户 | 用户本人费用累计 | 用户本人费用累计 | 仅该用户停止新云端调用 |
| 全局 | 所有计入全局的费用累计 | 所有计入全局的费用累计 | 全部用户停止新云端调用 |

同一笔用户费用计入本人和全局，但全局不因双层归属累计两次。任一适用额度不足即不允许新云端调用；只有用户日、用户月、全局日、全局月条件均允许，才可以恢复。

Q06-a 已确认：预算未填写显示“预算未配置”，不开放云端；0 表示无云端额度。全局与用户的日、月预算必须全部为有效正数且有剩余额度，才能发起该用户云端模型调用，首版不提供无限预算。本地模型、免费搜索与其他理财功能按各自可用性规则照常使用；免费搜索不因模型预算未配置或为零而被关闭。

每日北京时间 00:00、每月 1 日 00:00 开始新周期，历史记录保留。默认 80% 预警，100% 停止新云端调用并尝试合格本地模型；管理员可调整低于 100% 的预警阈值，不能关闭达上限停用规则。同预算同周期同阈值只提醒一次，重启后仍去重。

### 8.4 费用归属与异常计费（Q06-b、Q07 已采纳）

| 情形 | 产品规则 |
|---|---|
| 全局或用户日／月预算未配置 | 显示预算未配置，不开放该用户云端；不阻断本地、免费搜索及理财功能 |
| 预算为 0 | 无云端额度，首版不提供无限预算 |
| 用户主动调用／后台用户任务 | 计入所属用户与全局；管理员使用本人理财功能同样记账 |
| 管理员模型连接／能力测试 | 记为系统诊断费用，只计全局日月预算，不占任何个人额度；诊断元数据仅管理员可见 |
| 诊断预算检查 | 系统诊断也须有有效且有余额的全局日月额度，不因管理权限绕过上限；不要求以管理员个人额度替代诊断额度 |
| 重试与备用调用 | 保持原任务的用户／系统归属，每次可能计费的尝试均记录，不通过换模型重置额度 |
| 超时／未返回用量 | 标记待核实，保留保守预留或估算占用，不直接按零释放；缺乏可靠估算时暂停该费用来源的新云端调用，提示管理员处理 |
| 请求预计超过剩余额度 | 不发起新云端请求，只尝试用户已选择的合格本地候选，无候选则提示不足 |
| 跨日／跨月 | 每次请求按发起时的周期归属，结束后结算到原周期；新重试是新尝试，重新检查当前周期额度 |
| 调整额度与价格 | 不清空已用费用；调低后若超额即限制，调高后重查；已发请求继续按其价格快照结算 |
| 并发 | 调用前预留预计费用或采取等效限制；已有占用不可再次当成可用余额 |
| 厂商额外付费能力 | 未定义计价的内置搜索等功能不得隐式启用；独立搜索首版只用免费额度 |

系统诊断属于上述全局专属例外；用户业务仍须同时满足用户和全局四项预算条件。

### 8.5 预留、待核实与结算

- 页面区分已结算估算费用、进行中预留和待核实占用；预算可用余额扣除仍有效占用，不将预留直接展示为厂商最终扣费。
- 按当次模型配置、输入和输出上限估算，未知价格不自动按零处理；具体算法与厂商字段由 T02／T03 验证。
- 最终用量返回后，将同一次尝试的占用替换为结算值，不重复累计；取消后迟到用量仍可结算，但不得恢复已取消的业务结果。
- 管理员可依据上游记录核实并调整待核实费用，保留原状态、调整理由和脱敏记录，不静默删除占用以增加预算。
- 多轮任务每一步重新判断余额，不因为初始检查通过就无限执行；正在上游执行的调用可能继续计费，不承诺最终账单精确停在上限。
- 明细保留期不应删除仍需核实的最低计费依据；可保留不含正文的最小核对记录与汇总，直到结算完成，具体机制由 T03 明确。

- 不因切换模型而更换来源配置；AI 与页面通过一致的数据能力取数。

### 9.4 时效和缺失（Q10 已统一采纳）

| 状态 | 业务行为 |
|---|---|
| 正常交易中的新报价 | 正常计算，并展示所属时间 |
| 休市／停牌的有效最后报价 | 标记“最近交易价／停牌”，不按网络故障过期处理 |
| 主备都失败且有旧值 | 可显示最近成功估值，但明确非实时与统计不完整，不刷新来源时间 |
| 没有有效价格 | 市值／收益标不可得，不以零价制造大额亏损；总资产标未覆盖部分 |
| 财报、季报和基金持仓 | 展示报告期与披露日期，不使用与实时价格相同的分钟级过期阈值 |
| 新闻发布时间未知 | 明示未知，不据此断言“今日最新” |
| AI 使用降级数据 | 提示数据截至时间、缺失和推断限制，不能编造因果或数字 |

总资产可展示有依据的最近成功估值，但必须说明覆盖范围、旧值部分与缺价部分；不把部分估值标成完整实时总资产。缺少比较基准或有效价格时，不给出完整收益／风险结论。AI 必须继承同样的数据质量限制。过期阈值与统计覆盖门槛按数据类型在实施计划中定义和验证，不使用一个全局 TTL。

## 10. 独立网页搜索

### 10.1 已确认范围

搜索是独立服务功能，与模型厂商、云端／本地模式无绑定。管理员在数据中心配置通道及 Key，模型切换不改变搜索配置。仅本地模式仍可在线搜索，必须说明查询词会离开本机。

首版只接入少数有免费额度的通道，保留扩展；Tavily 仅为候选，不等于选定。搜索结果保留链接、内容摘要和可取得的发布时间，未获得正文时不得描述为已读全文。

当前通道免费额度耗尽，尝试其他已配置且确认有免费余额的通道；全部耗尽则提醒并暂停通用搜索，不自动付费，已有公开行情／资讯照常运行。模型预算耗尽不自动关闭剩余免费的搜索。

### 10.2 产品入口与免费额度（Q08 已统一采纳）

- 首版通过已有问答的检索步骤和来源列表提供搜索，不另建通用搜索门户；服务配置及调用独立，不依赖模型厂商搜索工具。
- 管理员控制公共通道启停、凭证和可用额度；用户可以单独关闭本人搜索，不把搜索开关绑定仅本地模式。已启用通道可供云端和本地模型使用。
- 提供全局免费额度状态及用户请求限额，防止单人耗尽；额度单位、周期和限制参数由实施计划按通道规则定义，私有查询正文不进入全局监控。
- 禁用自动付费路径并采用保守额度核算；无法确认下一次请求仍在免费范围内时暂停该通道，不靠“上次成功”推断免费。余额不可核实或存在无法关闭的自动付费风险时，不开放该通道自动调用。
- 免费额度耗尽按已配置通道顺序回退；全部耗尽或无法确认免费时提示用户，保留公开资讯与行情能力，不捏造“已联网检索”。
- 缓存命中、搜索和正文提取消耗分别记录，不将搜索次数或 credits 当成 Token；按服务真实规则恢复额度，未知余额不显示为零或无限。
- 不把持仓数量、成本、账号或凭证作为查询词；只发必要市场问题、标的及公开信息关键词。
- 搜索结果不能覆盖已验证行情，引用必须对应实际获得的来源；缺少正文不能称为已读全文。

免费额度查询、周期恢复、并发控制和具体服务在 T01／T03 验证，不承诺免费规则永久不变。

## 11. 通知与消息中心

### 11.1 渠道与个人选择

应用内默认提供。外部支持 PushPlus、邮件 SMTP、飞书 Webhook；默认推荐 PushPlus。每人可保存多个配置，但同一时间只启用一个，全部外部事件统一使用该渠道，不按事件拆分、不重复群发、不失败自动换渠道。

首次登录引导配置至少一个外部渠道，可稍后完成；未配置或全部停用时，持续显示待配置状态，仅不发送外部通知，不阻断业务及应用内提醒。

配置字段至少覆盖服务地址／Token／邮件 SMTP 端口与安全方式／账号与授权码／发收件地址等各渠道必需字段，保存不自动发测试消息，测试由用户明确触发。凭证脱敏、渠道配置按用户隔离。

### 11.2 接收人规则

| 事件 | 应用内接收人 | 外部接收人 |
|---|---|---|
| 用户简报、小结、私有风险、个人预算和模型切换 | 本人 | 使用本人当前外部渠道 |
| 全局预算、公共数据源故障、系统服务异常 | 管理员 | 使用管理员当前渠道 |
| 全局限制导致用户当前任务不可用 | 本人可见原因，不见他人明细 | 不强制向所有人重复发系统告警 |

Q02-d 已确认首版只有一个管理员，系统告警发送给该管理员，并使用其当前启用渠道；首版无需多管理员收件或值班路由。

### 11.3 消息生命周期（Q11 已统一采纳）

- 应用内统一记录通知，支持未读／已读、按时间查看和发送结果；普通用户只看本人，系统告警由唯一管理员接收。
- 渠道状态区分待发送、渠道已接受、失败、结果未知，渠道接受不等于收件人阅读；应用内已读独立维护。
- 确认未成功的临时故障可在同渠道有限重试，结果未知时不盲目重发以免重复；重试上限等技术参数由实施计划定义，不自动换渠道。
- 用户切换渠道只影响后续新通知；旧失败通知不自动转发，可由本人主动重发至当前渠道，触发时明确目标。
- 同一预算周期同阈值只告警一次；连续故障合并，不跨用户去重；由故障恢复为可用时发送一次恢复通知，不按轮询反复通知。
- 外部通知默认摘要，不发送完整持仓、交易流水或问答正文，具体结果在应用内查看；内网链接明确仅在网络可达时可打开。
- 通知记录的保留期可由管理员配置，其默认值在实施计划参数表给出；清理消息不能删除预算提醒去重和必须保留的费用依据。

上述参数由实施计划统一给出专业默认值，无需逐项重新征求同意；不能以参数设置改变已确认的单一渠道和私有数据边界。

## 13. 备份、恢复与数据保留

### 13.1 备份

已确认每天自动一次、自动备份默认保留 30 天，管理员可手动触发。只保存本机持久目录，包含数据库和恢复必需配置；文件可能含全部用户与敏感信息，应限制访问，不提供普通用户下载，也不提供管理员浏览他人业务正文的界面。

**Q12 已采纳**：错过定时备份后在下一次启动补做一次，不批量伪造历史备份；手动及恢复前保护备份单独标识，清理规则不得删除唯一有效恢复点。备份失败在应用内通知管理员，显示最近成功时间，当前外部渠道可用时按既定系统告警规则推送。手动及保护备份的具体清理参数在实施计划明确，不改变自动备份默认 30 天。

### 13.2 恢复

恢复前检查完整性与兼容性、自动保存当前状态；检查或保护性备份失败不覆盖。恢复期间进入维护态并暂停业务与后台写入，完成后再恢复服务。不能让旧执行任务继续把结果写入恢复后的数据库。

**Q12 已采纳**：恢复后所有旧会话失效，用户重新登录；旧进行中任务标记中断，不自动重发。恢复旧备份可能丢失已发生费用，因此先暂停新的云端模型调用，管理员核对费用及预算后再按额度规则恢复，不能直接使用回退后的旧余额继续消费。恢复不解除用户仅本地选择，也不把私有内容移交管理员。

本机备份不能承诺磁盘故障仍可恢复。7 天明细清理只约束在线业务库；30 天备份可能仍含更早明细，不能宣传为彻底删除。若需用户永久删除或合规擦除，是另外的产品范围。

| 日志与 Trace | 脱敏运行信息、阶段、错误码和耗时 | 不开放任意命令，不扩展他人数据权限 |

默认运行日志保留 7 天，管理员可调；Trace 默认关闭，临时开启默认 30 分钟后自动关闭，管理员可调。重启不能让 Trace 变成无限期。日志不包含密码、API Token、完整持仓、提示词、回答或私有工具结果。

测试结果显示执行时刻、范围、检查项、成功／失败、耗时与可理解原因。服务在运行不等于业务检查通过。回归任务占用、重复启动及失败终止策略在 T03 中设计，不提供任意命令执行或容器宿主机的通用管理控制台。

**Q14 已采纳**：关键管理动作保留操作者、时间、对象类型、动作及结果的脱敏审计记录，不保存凭证明文或用户内容；审计保留期限与运行日志分开配置，默认值在实施计划参数表统一给出。回归必须在独立测试环境运行，正常使用不强制长期运行测试容器；测试环境未准备或资源不足时显示无法执行，不能回退到真实业务数据执行测试。

## 15. 安全、可靠性与非功能要求

- 认证与授权在后端生效，不能只隐藏页面；所有用户资源标识必须验证归属。
- 密码非明文存储；密钥不出现在日志、页面明文、构建镜像或版本库；备份包含密钥时应说明恢复依赖和文件权限。
- 数据源、模型和搜索地址需校验，外部内容不能改变应用权限或触发未授权操作；具体策略在技术方案设计。
- 提供会话失效、用户停用、恢复维护的统一提示；不能把后端错误直接打印到用户界面。
- 私有云端上下文仅在所选服务的功能需要范围内发送，搜索词不含无关账户信息；第三方平台使用条款与凭证权限仍需用户自行具备。
- 展示数字须保留币种、单位、统计区间和来源，估算与事实区分；缺数据不得补零制造完整结论。
- 管理配置失败不覆盖有效配置；运行中修改按已确认 Q05 对后续调用重新检查，不改变已发请求的计价快照，不将已取消任务恢复。具体版本化机制由 T02 设计。
- 采用现有工程结构和依赖优先，不为需求文档预先承诺全新框架、数据库或中间件。
- 以个人／家庭少量用户为目标，非推理业务不得因本地模型排队整体阻塞。性能指标、参考硬件和并发样本在实施计划明确并验证，不写脱离硬件的统一 AI 响应秒数。
- 普通用户登录、资产查询、问答、模型偏好、用量与通知核心流程可在手机完成；管理员页面以桌面完整操作为主，手机能查看状态和必要告警，不承诺首版全部复杂管理表单均按手机重做。具体验收设备由 T04 明确。
