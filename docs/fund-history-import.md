# 基金历史交易补录

工具：`scripts/import_fund_history.py`。使用理财助手相同的 Python 环境和运行目录，不需要新增数据库表。

## 使用方法

在项目根目录执行，账号 ID 替换为实际导入账号：

```bash
# 默认只读预览，读取 position 工作表，平台为支付宝
LICAI_DATA_DIR="$PWD/runtime-data" python scripts/import_fund_history.py /path/to/funds.xlsx --user-id 1

# 核对后执行；先生成保护性备份，再以事务写入
LICAI_DATA_DIR="$PWD/runtime-data" python scripts/import_fund_history.py /path/to/funds.xlsx --user-id 1 --apply
```

可选参数：

| 参数 | 用途 |
| --- | --- |
| `--sheet position` | 指定明细工作表。只读取该表，不读取其他表。 |
| `--platform 支付宝` | 指定持有平台。同一账号、平台、基金代码匹配一个基金资产。 |
| `--fund-code 000711` | 仅处理指定六位代码。 |
| `--exclude-order ORDER_ID` | 明确排除某个来源订单，可重复指定。排除项必须在选定范围内存在，避免拼错后误导入。 |
| `--apply` | 实际写入；省略时只读预览，不建资产或流水，也不创建备份。 |

排除不确定记录时，先对照 Excel 订单号确认，再使用 `--exclude-order`。工具会列出排除项；不会因为校验失败而自动跳过记录。

## 表头和规则

第一行为表头。必填列：订单号、交易时间、交易类型、基金名称、基金代码、确认金额、确认份额、手续费、确认日期。允许其他列，组合基金名称会保留在来源备注中。空白行忽略。

- 长订单号必须在 Excel 中保存为文本。工具删除订单号中的空格及换行，但不能恢复 Excel 已丢失的数字精度；超过 15 位的数字单元格订单号会被拒绝。
- 基金代码恢复为六位文本，例如 `711` 转为 `000711`。基金份额支持小数。
- 日期支持真实 Excel 日期、`YYYY/MM/DD HH:MM`、`YYYY-MM-DD HH:MM`、含秒及仅日期形式。
- 金额必须为非负数且精确到分，份额最多六位小数。非法行、未知交易类型和重复表头会报出位置并停止。

| 原业务 | 入账 | 金额、份额和费用 |
| --- | --- | --- |
| 定投买入、用户买入、用户跨 TA转换、用户转换 | `BUY` | 确认金额作为含费总成本，确认份额作为份额；推算净值＝（确认金额－手续费）÷确认份额。手续费仅记录，不重复增加成本。 |
| 营销买入 | `BUY` | 平台赠送，金额、净值及手续费均记零，只增加确认份额。原确认金额留在来源备注中。 |
| 用户卖出 | `REDEEM` | 确认金额作为扣费后的实际到账金额、确认份额作为赎回份额；手续费单独记录，推算成交净值＝（确认金额＋手续费）÷确认份额。收益按实际到账金额计算，不重复扣费。 |
| 机构分红 | `DIVIDEND` | 全部按现金分红处理：确认金额为现金收入，确认份额和手续费须为零。与此不符的记录需先核对或明确排除。 |

`trade_date` 使用交易/申请日期，`trade_time` 保留小时分钟；确认日期及确认时刻保存在流水来源备注中。源数据已给出确认结果，因此导入状态为 `confirmed`。转换按买入处理，不凭空创建对应转出交易。

## 数据写入和重复处理

基金持仓写入 `external_assets`（`asset_type=FUND`），历史写入 `external_asset_actions`。不写入股票表、不生成未来定投计划、不请求历史行情。

来源订单、原业务、确认日期、原确认金额和源行号以 `fund-history:v1|` 开头的 JSON 保存到流水备注中。不要手工删除或改写这个标记及订单信息，否则重复导入时不能可靠匹配。

- 同账号、同平台、同基金代码下，同订单号且内容相同的记录跳过；源文件行号或排序变化不会重复入账。
- 同订单号的金额、份额、费用、日期或业务内容发生变化，整次导入失败。需先核对，不会自动覆盖已有流水。
- 同一基金在同平台已有多个资产，或者已有持仓却没有流水，工具拒绝自动合并或覆盖。已归档资产有新增流水时，需先确认并重新启用，避免补录后仍从在持列表隐藏。
- 旧持仓自动迁移生成的 `initial (auto-migrated)` 流水是快照，不是可直接叠加的真实交易历史；存在这类快照时拒绝新增，须先核对期初来源，避免持仓重复累计。
- 已有手工流水若与新增记录同日同类但没有来源订单号，要求先核对，避免把同一交易再次导入。其他日期的人工记录可保留，并与新记录一起重算。
- 每次有实际新增时，先备份再写入；备份失败不写入。写入失败整次回滚。无新增时不重复创建备份。

## 五年记录和后补历史

允许只导入现有五年数据，不自动生成零成本期初仓位。预览和基金资产备注都会说明：历史未完整前，份额、成本及盈亏仅反映已录入记录，不能视为完整持仓。

若某日赎回超过此前已录入份额，工具提示缺失期初/流水缺口，仍保留这笔真实赎回。现有账本对未知成本无法准确结转；在补齐前，展示份额及盈亏可能不准确。

后续可把更早的真实交易整理成相同表头，再导入同账号、同平台。工具将旧、新流水一并按历史日期和交易时刻重算；没有时刻的旧流水按当天零点排序，同一时刻再按流水 ID 排序。若在页面手动添加历史流水，使用原始日期及已知时刻并核对重算结果；将来同一笔也出现在 Excel 中时，要先处理与人工流水的重叠。

### 在页面补录现金分红

在基金持仓的「流水」弹窗右上角点击「补录现金分红」，填写真实到账日期、实际到账金额和可选备注。到账日期支持往年日期，不得晚于今天；金额须大于零。使用「保存并继续」可连续补录，日期保留，金额与备注清空；保存失败会保留输入以便重试。

分红保存为已确认的 `DIVIDEND` 流水，按历史日期计入已实现收益，不增加持有份额。此入口仅用于现金分红，不适用于红利再投资。录入前核对已有记录，避免同一笔分红既手动补录又通过文件导入。

接口：`POST /api/assets/{asset_id}/dividends`，请求字段为 `amount`（到账金额）、`trade_date`（`YYYY-MM-DD`）、`note`（可选）。仅可为当前账号的基金录入；返回新增流水 `id` 和重算后的 `state`。

### 基金成本与收益口径

基金采用移动加权平均：买入时将含申购费的实际支出并入剩余成本，再除以总份额；部分赎回按赎回前的平均成本结转，因此不会单独改变平均成本价。赎回净到账减去结转成本计入已实现盈亏；赎回金额已扣费，不再重复扣手续费。

现金分红不扣减默认展示的持有成本；基金默认展示持有收益，对齐已核对的支付宝口径：持有收益＝已确认市值－剩余平均成本＋归属于剩余持仓的现金分红，持有收益率＝持有收益÷剩余平均成本×100%。金额分项先保留到分，再计算收益。待确认申购金额不参与收益计算。

每次部分赎回时，按赎回份额占赎回前总份额的比例，将对应分红移出持有收益；清仓时持有分红清零，再买入不会继承旧持仓的分红。份额拆分不改变分红金额。全部历史分红仍保留在已实现总账中，不会因赎回丢失。

累计总收益＝持有收益＋全部已实现收益－持有收益已包含的分红。接口用 `holding_dividend` 表示剩余持仓分红；总账补入收益时扣除该部分以避免重复计入。`diluted_cost` 仍是扣除本周期已实现收益后的独立摊薄指标，不作为基金默认持有成本。

补录、修改或删除历史流水后，按日期及时刻重新回放计算。原始交易净值、金额及份额保留；份额批次仍按先入先出扣减以保留剩余份额的持有日期，其成本分配属于平均成本账本，不代表原始成交净值。清仓再买入后，以新买入支出计算新持有成本。加密资产及股票维持各自原有算法。

建议最后用支付宝的当前持有份额逐只核对，不以账本推算结果代替平台对账。
