# A03 验收记录：登录会话与前端账号切换

日期：2026-10-15。分支：`codex/p0-foundation-protection`。
后端实现：`4993af8`；前端实现：`21093b5`。

## 实现范围

- `services/auth.py` 复用 A02 的 users/sessions，无数据库迁移或新增第三方依赖。
  每次登录生成独立 256 bit 不透明凭据，仅存摘要；UserContext 由服务端构造。
- 固定 30 天、多设备共存，状态查询不续期；退出仅撤当前会话，改密／重置撤销本人所有旧会话。
  登录和每次 HTTP 鉴权检查 active/auth_version；管理员恢复沿用 A02 的撤销能力。
- 临时密码只能查看本人登录状态、修改密码和退出；业务 HTTP、媒体 API 及 WebSocket 握手均阻止进入。
- 登录、状态、退出、改密 API；JSON／正文大小校验、脱敏错误、HttpOnly/SameSite Cookie、
  HTTPS Secure、CSRF、Origin、no-store，以及同事务的脱敏登录／退出／改密审计。
- React 初始化／登录／改密表单及账号操作条；既有直接请求和流式请求接入共同认证请求层。
- 账号变化重载文档以重建页面及模块级问答缓存；统一 401 清预取与私人持久缓存、取消旧请求／流；
  旧代际正文和已排队的流块均拒绝；WebSocket 卸载时清理连接、重连与每代心跳。
  同浏览器标签页共享 Cookie，账号变化通知其他标签页重新检查身份。
- 已有 10 项业务 HTTP 测试改为通过真实初始化／登录夹具调用，不在生产代码添加测试身份绕过。

## 先失败再通过

1. 后端初始 6 项因 auth 模块／登录路由缺失失败，补实现后通过。
2. 前端初始 4 项因会话请求层和连接管理模块缺失失败，补实现后通过。
3. WebSocket 匿名／跨 Origin 握手回归先失败，加入门禁后通过。
4. 独立审查发现正文异常被吞、持仓分析持久缓存残留及 SSE 提前解除取消监听。
   补充正文／缓存／流取消测试，修复后通过。
5. 浏览器发现 204 被表示为空流，重建 Response 报错导致退出后页面不跳转；补回归先失败，
   无正文状态跳过流重建后通过，浏览器复测退出成功。
6. 复核发现包装流预取的队列仍可保留旧 chunk；先失败测试重现，取消时主动使流失效并取消 reader，
   现前端会话 10 项全部通过。
